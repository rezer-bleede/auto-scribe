How AI Coding Agents Plan, Use Tools, and Ship Software

An AI coding agent starts with a goal, not a cursor. Give it "add rate limiting to this endpoint" and it reads the codebase, writes the patch, runs the tests, and iterates until they pass. The capability that makes this work is not a bigger model. It is a disciplined loop: plan, act, observe, verify. This article breaks down how that loop works and what it changes for the people who build with it.

Beyond Autocomplete

Autocomplete predicts the next token. An agent pursues the next outcome. The difference is not degree but kind: the agent takes actions, observes results, and decides what to do next, while the model behind it only proposes text. Every capability an agent has, editing files, running tests, searching code, arrives through that loop.

The loop itself is simple to describe: gather context, propose a step, execute it, read the outcome, repeat. The engineering lives in what each step actually does.

Planning: Turning Intent into Steps

A prompt like "fix the flaky login test" is not executable. It is a goal. Before touching code, a competent agent decomposes the goal into smaller, verifiable units. Effective planning looks like:

  • Task decomposition — break the goal into ordered steps: reproduce, diagnose, patch, validate.
  • Explicit task lists — keep a checklist the model re-reads every turn, so long sessions do not drift from the original goal.
  • Exploration before mutation — search the codebase with grep, glob, and dependency graphs before editing a single file.
  • Replanning on failure — when a test fails or an assumption breaks, revise the plan instead of retrying the last edit.

Good plans are boring and incremental. Agents that fail in demos usually fail because they attempted too much in one step and could not tell which step went wrong.

Tool Use: The Agent's Hands

The model cannot edit files or run commands. It can only request them. Every capability comes from tools exposed through a structured interface, often an MCP server or a built-in registry. A typical agent wields:

  • File tools — read, write, and edit with exact-match find-and-replace.
  • Shell tools — run builds, tests, linters, and git commands.
  • Search tools — grep the codebase, glob for files, and query the web for documentation.

A tool call is structured data. This is what an agent emits to run a test suite, and what it gets back:

{
  "tool": "bash",
  "input": { "command": "pytest tests/test_login.py -x" }
}

{
  "exit_code": 1,
  "stdout": "FAILED test_login.py::test_refresh_token - KeyError: 'exp'"
}

The model reads that failure, forms a hypothesis about the missing claim, opens the relevant file, and proposes a fix. The loop is not mystical. It is a fast developer with perfect recall and no keyboard.

Context Is the Real Bottleneck

An agent's working memory is its context window, and it fills fast. File dumps, test output, and tool results pile up until the model loses the thread. Serious agent systems spend as much effort on context management as on prompting: truncating large outputs, summarizing completed steps, and re-injecting the task list. Agent capability is bounded less by the model's IQ than by how well the harness curates what the model gets to see.

Verification: The Loop That Matters

Unverified generation is expensive guessing. What separates a usable agent from a toy is that every meaningful change gets checked — tests run, linters pass, diffs reviewed. As the saying goes in the eval community:

The model is not the risk. The loop without verification is the risk.

This is why guardrails exist: permission prompts for destructive commands, sandboxed execution for untrusted input, and human review before anything is pushed. An agent that can verify its own work still cannot be trusted to approve its own pull request.

What Changes for Developers

When implementation gets cheap, judgment becomes the job. In practice that means:

  • Spec-writing replaces code-writing — clear acceptance criteria are the new function signatures.
  • Review becomes the core skill — reading a machine's 300-line diff quickly and well is a superpower.
  • Test suites become the ceiling — agents go exactly as far as your verification lets them.

AI coding agents are not autonomous engineers. They are tireless executors paired with a plan they can barely see past. The teams shipping real value with them treat the agent as the fastest junior on the roster: unlimited energy, zero tenure, and every line of its work held to the same bar as any other contributor's. Build the loop well, and the shipping takes care of itself.
